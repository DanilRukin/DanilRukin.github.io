Привет, друзья! Сегодня мы берем быка за рога и реализуем самого старого, самого простого, но до сих пор одного из самых эффективных оптимизаторов — **SGD, или стохастический градиентный спуск**.

Знаете, SGD в мире оптимизаторов — это как хороший молоток в ящике с инструментами. Появились уже и электрошуруповерты (Adam), и умные лазерные уровни, но молоток все еще нужен. Потому что он простой, надежный, и ты всегда понимаешь, что делаешь.

## Базовый класс: Фундамент для всех оптимизаторов

Прежде чем нырять в SGD, давайте посмотрим на базовый класс, от которого танцуют все наши оптимизаторы:

```csharp
public abstract class Optimizer
{
    protected readonly List<Tensor> _parameters;  // Что оптимизируем
    protected readonly double _learningRate;      // Размер шага

    protected Optimizer(List<Tensor> parameters, double learningRate)
    {
        _parameters = parameters;
        _learningRate = learningRate;
    }

    public abstract void Step();      // Сделать шаг оптимизации
    public abstract void ZeroGrad();  // Обнулить градиенты
}
```

**Что здесь важно?**

- `_parameters` — это список тензоров, которые мы хотим оптимизировать. Обычно это веса и смещения всех слоев сети.
- `_learningRate` — наш «размер шага», самый важный гиперпараметр.
- `Step()` — метод, который обновляет веса на основе градиентов.
- `ZeroGrad()` — метод, который зануляет градиенты после шага (иначе на следующей итерации они накопятся).

Это минимальный контракт, который должен выполнять любой оптимизатор. Хоть SGD, хоть Adam, хоть какой-нибудь экзотический оптимизатор из научной статьи.

## SGD: Простота — это гениально

А теперь смотрите на реализацию SGD. Она настолько простая, что кажется, будто тут что-то не так:

```csharp
public class SGD : Optimizer
{
    private readonly double _momentum;
    private readonly List<Tensor> _velocities;

    public SGD(List<Tensor> parameters, double learningRate = 0.01, double momentum = 0.0) :
        base(parameters, learningRate)
    {
        _momentum = momentum;
        _velocities = new List<Tensor>();

        foreach (var param in parameters)
        {
            _velocities.Add(new Tensor(param.Shape));
        }
    }
```

**Разберем конструктор:**

1. `parameters` и `learningRate` уходят в базовый класс.
2. `momentum` — это дополнительный параметр. По умолчанию 0.0, то есть SGD без момента.
3. `_velocities` — список тензоров той же формы, что и параметры. Зачем? Чтобы хранить «скорость» движения для каждого параметра. Это нужно только если мы используем момент.

## Шаг SGD: Два режима работы

Метод `Step()` — это сердце оптимизатора. У него есть два режима: простой (без момента) и продвинутый (с моментом).

### Режим 1: Классический SGD (без момента)

```csharp
if (_momentum > 0)
{
    // Режим с моментом (рассмотрим позже)
}
else
{
    // param -= lr * grad
    for (int j = 0; j < param.Size; j++)
    {
        param.Data[j] -= _learningRate * grad.Data[j];
    }
}
```

**Формула:** `param = param - learning_rate * gradient`

Это просто вычитание градиента, умноженного на learning rate. Каждый параметр обновляется независимо, опираясь только на свой градиент.

**Пример с числами:**

Допустим, у нас есть вес `w = 1.5`, градиент `dw = 0.1`, learning rate = 0.01:

```
новый w = 1.5 - 0.01 * 0.1 = 1.5 - 0.001 = 1.499
```

Вес чуть-чуть уменьшился. Если градиент положительный, значит, увеличение веса увеличивает ошибку, поэтому мы вес уменьшаем. Если градиент отрицательный, увеличение веса уменьшает ошибку, поэтому мы вес увеличиваем (минус на минус дает плюс).

### Режим 2: SGD с моментом

```csharp
if (_momentum > 0)
{
    // v = momentum * v - lr * grad
    // param += v
    Tensor velocity = _velocities[i];

    for (int j = 0; j < param.Size; j++)
    {
        velocity.Data[j] = _momentum * velocity.Data[j] - _learningRate * grad.Data[j];
        param.Data[j] += velocity.Data[j];
    }
}
```

**Формулы:**

```
velocity = momentum * old_velocity - learning_rate * gradient
param = param + velocity
```

**Что здесь происходит?**

1. Мы берем старую скорость (`old_velocity`), умножаем на момент (обычно 0.9). Это сохраняет инерцию движения.
2. Вычитаем текущий градиент, умноженный на learning rate. Это новое направление.
3. Обновляем параметр, добавляя скорость.

**Пример с числами:**

Предположим:

- Старая скорость `v = 0.2`
- Момент = 0.9
- Градиент = 0.1
- Learning rate = 0.01

```
новая скорость = 0.9 * 0.2 - 0.01 * 0.1 = 0.18 - 0.001 = 0.179
новый вес = старый вес + 0.179
```

Видите? Скорость затухает, но не мгновенно. Инерция сохраняется.

## Почему момент так важен?

Представьте, что вы катите шар с горки. Без момента шар останавливается, как только кончается склон. С моментом он продолжает катиться по инерции.

В мире нейросетей это дает два преимущества:

### 1. Сглаживание осцилляций

Представьте узкий овраг: градиент постоянно дергает то влево, то вправо. Без момента веса будут скакать туда-сюда, почти не продвигаясь вдоль оврага.

С моментом эти осцилляции усредняются. Влево-вправо дергает, но инерция накапливается вдоль оврага. Шар катится, а не трясется.

### 2. Преодоление локальных минимумов и седловых точек

Мелкая ямка? Шар с инерцией просто перекатится через нее. Плоское плато? Инерция поможет его пересечь, не останавливаясь.

## Анатомия обновления: Разбор цикла

Давайте детально разберем, что происходит в циклах:

```csharp
for (int i = 0; i < _parameters.Count; i++)
{
    Tensor param = _parameters[i];
    Tensor? grad = param.Grad;

    if (grad == null) continue;  // Нет градиента — нечего обновлять

    // ... обновление параметра ...
}
```

**Важные моменты:**

1. Мы обходим **все** параметры сети. Каждый вес и каждое смещение получают свое обновление.
2. Проверяем `grad == null`. Некоторые параметры могут не иметь градиента (например, если `requires_grad = false`).
3. Для каждого параметра мы работаем с его данными напрямую, через `param.Data[j]`. Это низкоуровневый доступ, но он дает полный контроль.

## ZeroGrad: Зачем обнулять градиенты?

Метод `ZeroGrad` обманчиво прост:

```csharp
public override void ZeroGrad()
{
    foreach (var param in _parameters)
    {
        param.ZeroGrad();
    }
}
```

Но зачем это нужно?

**Проблема:** Градиенты накапливаются. Если мы не обнулим их после шага, на следующей итерации к новым градиентам добавятся старые.

**Аналогия:** Представьте, что вы идете по компасу. После каждого шага вы должны сбрасывать компас, чтобы новое направление считалось от текущей позиции, а не от старой. ZeroGrad — это сброс компаса.

## Простой пример работы SGD

Давайте представим, как SGD работает с простой линейной регрессией:

```csharp
// У нас есть один вес и одно смещение
List<Tensor> parameters = new List<Tensor> {
    new Tensor([0.5], requiresGrad: true),  // вес
    new Tensor([0.1], requiresGrad: true)   // смещение
};

// Создаем SGD с learning rate 0.01 и моментом 0.9
var sgd = new SGD(parameters, learningRate: 0.01, momentum: 0.9);

// В процессе обучения:
// 1. Считаем предсказания
// 2. Считаем loss
// 3. Вызываем loss.Backward() — градиенты записались в параметры
// 4. sgd.Step() — обновляем веса
// 5. sgd.ZeroGrad() — готовимся к следующей итерации
```

**Что происходит внутри Step() для веса:**

1. Берем градиент веса (например, 0.2)
2. Берем старую скорость для этого веса (например, 0.1)
3. Вычисляем новую скорость: `0.9 * 0.1 - 0.01 * 0.2 = 0.09 - 0.002 = 0.088`
4. Обновляем вес: `0.5 + 0.088 = 0.588`

Вес увеличился, потому что градиент был положительным, значит, увеличение веса уменьшает ошибку.

## Почему SGD до сих пор жив?

В эпоху Adam может показаться, что SGD устарел. Но нет!

### 1. Интерпретируемость

SGD прост и прозрачен. Вы точно знаете, что каждый шаг — это движение против градиента. Никакой адаптивной магии.

### 2. Меньше памяти

SGD не хранит дополнительных статистик (кроме скорости при моменте). Adam хранит два дополнительных тензора на каждый параметр — это удваивает использование памяти!

### 3. Лучшее обобщение

Есть исследования, показывающие, что SGD с моментом часто находит решения с лучшей способностью к обобщению, чем Adam. Особенно в компьютерном зрении.

### 4. Проверен временем

SGD используется десятилетиями. Его поведение изучено вдоль и поперек. Это предсказуемый, надежный инструмент.

## Когда использовать SGD?

**Идеально для:**

- Компьютерного зрения (особенно с косинусным затуханием learning rate)
- Задач, где важна интерпретируемость
- Случаев, когда память критична (огромные модели)
- Когда вы точно знаете, какой learning rate нужен

**Не очень подходит для:**

- NLP задач с разреженными градиентами (там Adam рулит)
- Ситуаций, где нужно быстро протестировать гипотезу (Adam быстрее сходится)
- Очень шумных градиентов (момент помогает, но Adam адаптируется лучше)

## Расширения и вариации

Наш SGD можно легко расширить:

### Weight decay (L2 регуляризация)

```csharp
// Добавляем штраф за большие веса
gradWithWeightDecay = grad + weightDecay * param;
```

### Nesterov momentum

```csharp
// Сначала делаем шаг по инерции, потом считаем градиент
paramTemp = param + momentum * velocity;
// ... считаем градиент для paramTemp ...
```

### Learning rate scheduling

```csharp
// Уменьшаем learning rate со временем
if (step % decaySteps == 0)
    learningRate *= decayRate;
```

## Заключение: Простота — это сила

Иногда самые простые решения оказываются самыми надежными. SGD не пытается адаптироваться к каждому параметру индивидуально, не хранит сложных статистик, не делает ничего лишнего. Он просто берет градиент и делает шаг в противоположном направлении. Снова и снова. Тысячи, миллионы раз.

И этого часто достаточно, чтобы достичь вершины.

В нашей реализации мы сохранили эту простоту, добавив опцию момента для тех случаев, когда нужна инерция. Получился инструмент, который:

- **Прост** для понимания и отладки
- **Гибок** (с моментом или без)
- **Эффективен** по памяти
- **Проверен** временем

В следующей статье мы реализуем Adam — умного, адаптивного, современного. Но помните: даже за самым навороченным смартфоном стоит простая идея электричества. Так и за Adam стоит простая идея SGD. Поймешь SGD — поймешь все оптимизаторы.
