Привет, друзья! Сегодня мы беремся за короля современных оптимизаторов — **Adam**. Если SGD — это упрямый пешеход, который методично топает вниз по склону, то Adam — это опытный альпинист с целым рюкзаком хитрых приборов. Он не просто идет, он анализирует рельеф, подстраивается под местность и принимает обоснованные решения на каждом шагу.

## Что такое Adam и зачем он нужен?

Adam (Adaptive Moment Estimation) — это оптимизатор, который объединяет лучшее из двух миров:

1. **Momentum** — запоминает направление движения (как SGD с моментом)
2. **Adaptive learning rates** — подбирает индивидуальный размер шага для каждого параметра (как RMSprop или Adagrad)

Родился Adam в 2014 году (по меркам глубокого обучения — вчера) и моментально завоевал мир. Сегодня это, пожалуй, самый популярный оптимизатор. Почему? Потому что он **работает "из коробки"** с кучей разных задач и прощает ошибки в выборе гиперпараметров.

## Конструктор: Подготовка снаряжения

Давайте заглянем в конструктор Adam и посмотрим, что у него в рюкзаке:

```csharp
public class Adam : Optimizer
{
    private readonly double _beta1;
    private readonly double _beta2;
    private readonly double _epsilon;
    private int _step;

    private readonly List<Tensor> _m;
    private readonly List<Tensor> _v;

    public Adam(List<Tensor> parameters, double learningRate = 0.001, double beta1 = 0.9,
        double beta2 = 0.999, double epsilon = 1e-8) : base(parameters, learningRate)
    {
        _beta1 = beta1;
        _beta2 = beta2;
        _epsilon = epsilon;
        _step = 0;

        _m = new List<Tensor>();
        _v = new List<Tensor>();

        foreach (var param in parameters)
        {
            _m.Add(new Tensor(param.Shape)); // Первый момент (среднее градиентов)
            _v.Add(new Tensor(param.Shape)); // Второй момент (среднее квадратов градиентов)
        }
    }
```

**Разберем параметры:**

- `learningRate = 0.001` — размер шага. Для Adam стандартное значение 0.001 работает почти всегда.
- `beta1 = 0.9` — скорость затухания для первого момента. Как сильно мы помним старые градиенты.
- `beta2 = 0.999` — скорость затухания для второго момента. Как сильно мы помним старые квадраты градиентов.
- `epsilon = 1e-8` — маленькое число, чтобы избежать деления на ноль.

**Два ключевых массива:**

- `_m` (как от "moment") — хранит экспоненциально затухающее среднее градиентов. Это наша "инерция".
- `_v` (как от "velocity") — хранит экспоненциально затухающее среднее квадратов градиентов. Это наша "адаптивность".

Для каждого параметра сети мы храним два дополнительных тензора. Да, Adam требует в 3 раза больше памяти, чем SGD (сам параметр + m + v). Но оно того стоит!

## Шаг Adam: Четыре акта драмы

Метод `Step()` в Adam — это целый спектакль в четырех действиях. Давайте разберем каждое.

### Акт 1: Обновление первого момента (инерция)

```csharp
for (int j = 0; j < param.Size; j++)
{
    m.Data[j] = _beta1 * m.Data[j] + (1 - _beta1) * grad.Data[j];
}
```

**Формула:** `m_t = β₁ * m_{t-1} + (1 - β₁) * g_t`

Что здесь происходит? Мы берем старую инерцию (`m.Data[j]`), умножаем на `beta1` (обычно 0.9), и добавляем текущий градиент, умноженный на `(1 - beta1)`.

**Простая аналогия:** Представьте, что вы ведете дневник погоды. Каждый день вы записываете новую температуру, но старые записи тоже учитываете, просто с меньшим весом. Через месяц у вас будет "сглаженный" профиль температуры, где вчерашний день влияет больше, чем день недельной давности.

**Эффект:** Если градиенты постоянно указывают в одну сторону, `m` накапливается и создает инерцию. Если градиенты шумные и дергаются, `m` их сглаживает.

### Акт 2: Обновление второго момента (адаптивность)

```csharp
for (int j = 0; j < param.Size; j++)
{
    v.Data[j] = _beta2 * v.Data[j] + (1 - _beta2) * grad.Data[j] * grad.Data[j];
}
```

**Формула:** `v_t = β₂ * v_{t-1} + (1 - β₂) * g_t²`

Здесь мы работаем с **квадратами** градиентов. Зачем? Чтобы понять, насколько велики градиенты в среднем.

**Аналогия:** Вернемся к дневнику погоды. Теперь мы записываем не температуру, а квадрат температуры. Зачем? Чтобы понять разброс. Если температура скачет от -10 до +10, квадраты будут от 100 до 100 — разброс виден сразу. Если температура стабильна около 20, квадраты будут около 400.

**Эффект:** `v` показывает, насколько "активен" параметр. Если градиенты большие, `v` большой, и шаги будут мельче. Если градиенты маленькие, `v` маленький, и шаги будут крупнее.

### Акт 3: Коррекция смещения (исправляем несправедливость)

```csharp
double mHat = 1.0 / (1.0 - Math.Pow(_beta1, _step));
double vHat = 1.0 / (1.0 - Math.Pow(_beta2, _step));
```

**Зачем это нужно?**

В начале обучения `m` и `v` инициализируются нулями. Первые несколько шагов они будут смещены в сторону нуля. Это как если бы ваш дневник погоды первые дни показывал "в среднем 0", хотя на улице +20.

Коррекция смещения "разгоняет" оценки в начале обучения:

- На первом шаге (`_step = 1`): `mHat = 1/(1-0.9) = 10` — усиливаем первый момент в 10 раз!
- На десятом шаге: `mHat = 1/(1-0.9^10) ≈ 1/(1-0.348) ≈ 1.53` — уже почти не нужно
- На сотом шаге: `mHat ≈ 1/(1-0.9^100) ≈ 1/(1-≈0) ≈ 1` — коррекция исчезает

Та же логика для `vHat`, только с `beta2 = 0.999` коррекция длится дольше.

### Акт 4: Обновление параметров (финальный шаг)

```csharp
for (int j = 0; j < param.Size; j++)
{
    double mCorrected = m.Data[j] * mHat;
    double vCorrected = v.Data[j] * vHat;

    param.Data[j] -= _learningRate * mCorrected / (Math.Sqrt(vCorrected) + _epsilon);
}
```

**Формула:** `θ_t = θ_{t-1} - α * m̂_t / (√v̂_t + ε)`

Это кульминация! Давайте разберем по частям:

- `mCorrected` — скорректированная инерция. Направление и сила движения.
- `√vCorrected` — корень из скорректированной дисперсии. Мера активности параметра.
- `α * mCorrected / (√vCorrected + ε)` — адаптивный шаг.

**Что происходит?**

Если параметр имеет большие градиенты (`√v` большой), шаг автоматически уменьшается. Если градиенты маленькие, шаг увеличивается. Это позволяет Adam **подбирать индивидуальный learning rate для каждого параметра**!

**Пример с числами:**

Представьте два параметра с разными градиентами:

**Параметр A (редко обновляется):**

- m = 0.1, √v = 0.01
- Шаг = 0.001 \* 0.1 / (0.01 + 1e-8) = 0.0001 / 0.01 = 0.01
- Относительно большой шаг, чтобы сдвинуть "ленивый" параметр

**Параметр B (часто обновляется):**

- m = 0.1, √v = 1.0
- Шаг = 0.001 \* 0.1 / (1.0 + 1e-8) = 0.0001 / 1.0 = 0.0001
- Маленький шаг, чтобы не перелететь для "активного" параметра

Один и тот же learning rate (0.001) дал шаги, отличающиеся в 100 раз, в зависимости от истории градиентов!

## Визуализация работы Adam

Давайте представим, как Adam работает с одним параметром во времени:

```
Шаг 1: m = 0.1, v = 0.01
       Коррекция: mHat = 10, vHat = 1000
       Шаг: 0.001 * (0.1*10) / (√(0.01*1000) + ε) = 0.001 * 1 / (√10 + ε) ≈ 0.0003

Шаг 10: m = 0.15, v = 0.05
        Коррекция: mHat ≈ 1.5, vHat ≈ 1.05
        Шаг: 0.001 * (0.15*1.5) / (√(0.05*1.05) + ε) ≈ 0.001 * 0.225 / 0.23 ≈ 0.001

Шаг 100: m = 0.2, v = 0.1
         Коррекция: mHat ≈ 1.0, vHat ≈ 1.0
         Шаг: 0.001 * 0.2 / √0.1 ≈ 0.001 * 0.2 / 0.316 ≈ 0.00063
```

Видите, как шаг адаптируется? Сначала маленький (разгоняемся), потом нормальный, потом опять уменьшается (приближаемся к минимуму).

## Полный цикл: Как Adam работает в обучении

Давайте проследим полный цикл использования Adam:

```csharp
// Создаем оптимизатор для всех параметров сети
var optimizer = new Adam(model.Parameters(), learningRate: 0.001);

for (int epoch = 0; epoch < 100; epoch++)
{
    foreach (var batch in dataLoader)
    {
        // 1. Прямой проход
        var predictions = model.Forward(batch.Input);

        // 2. Вычисление loss
        var loss = lossFunction.Compute(predictions, batch.Targets);

        // 3. Обратный проход (накопление градиентов)
        loss.Backward();

        // 4. Шаг оптимизатора (обновление весов)
        optimizer.Step();

        // 5. Обнуление градиентов
        optimizer.ZeroGrad();
    }
}
```

**Что происходит внутри Step() для всей сети?**

Adam проходит по каждому параметру:

1. Берет его градиент (накопленный за батч)
2. Обновляет первый момент `m` (инерция)
3. Обновляет второй момент `v` (адаптивность)
4. Корректирует смещение
5. Вычисляет адаптивный шаг
6. Обновляет параметр

И так для миллионов параметров, на каждой итерации. И это работает!

## Гиперпараметры Adam: Что за что отвечает?

### learning_rate (α) = 0.001

Базовый размер шага. Для Adam 0.001 — это "святое число". Оно работает в 90% случаев. Иногда уменьшают до 0.0001 для тонкой настройки, иногда увеличивают до 0.01 для простых задач.

### beta1 (β₁) = 0.9

Скорость затухания первого момента. Определяет, как быстро "забываются" старые градиенты.

- β₁ = 0.9 → помним примерно 10 шагов
- β₁ = 0.99 → помним примерно 100 шагов (более гладкая инерция)
- β₁ = 0.8 → помним примерно 5 шагов (быстрее реагируем на изменения)

### beta2 (β₂) = 0.999

Скорость затухания второго момента. Определяет, как быстро "забываются" старые квадраты градиентов.

- β₂ = 0.999 → помним примерно 1000 шагов (очень долгая память)
- β₂ = 0.99 → помним примерно 100 шагов

Зачем так долго помнить? Чтобы оценка дисперсии была стабильной. Градиенты могут сильно меняться, но их "типичный размер" меняется медленно.

### epsilon (ε) = 1e-8

Крошечная добавка, чтобы избежать деления на ноль. Если `√v` близок к нулю (параметр почти не обновлялся), ε не дает шагу стать бесконечным. Обычно не трогают.

## Преимущества Adam перед SGD

### 1. Не нужно подбирать learning rate

С SGD вы можете потратить дни на поиск правильного learning rate. С Adam ставите 0.001 — и работает.

### 2. Адаптивность к разреженным данным

В NLP многие параметры обновляются редко (редкие слова). Adam автоматически делает для них шаги побольше, для частых слов — поменьше.

### 3. Устойчивость к масштабу градиентов

Если одни градиенты в среднем 0.1, а другие — 10, Adam сам выровняет шаги. С SGD пришлось бы вручную масштабировать.

### 4. Быстрая сходимость

Adam часто достигает хорошего качества за меньшее число эпох, особенно на сложных задачах.

## Недостатки Adam

### 1. Память

Требует в 3 раза больше памяти, чем SGD. Для гигантских моделей (LLM) это критично.

### 2. Иногда хуже обобщается

Есть исследования, что Adam может находить решения с чуть худшей способностью к обобщению, чем SGD с правильным learning rate scheduling.

### 3. Сложнее теоретически анализировать

SGD прост и прозрачен. Adam — черный ящик с кучей эвристик.

### 4. Может "переадаптироваться"

Иногда Adam так подстраивается под данные, что перестает двигаться в нужном направлении.

## Вариации Adam

### AdamW

Исправляет реализацию weight decay. В обычном Adam weight decay смешивается с learning rate, в AdamW они разделены. Сейчас стандарт.

### Nadam

Adam с Nesterov momentum. Чуть быстрее сходится на некоторых задачах.

### RAdam

Rectified Adam — исправляет проблему с большим разбросом в начале обучения.

### AMSGrad

Вариант, который гарантирует, что learning rate не увеличивается (только уменьшается).

## Когда использовать Adam?

**Идеально для:**

- Начала любого проекта (просто попробуйте Adam с learning rate 0.001)
- NLP задач (трансформеры, эмбеддинги, разреженные данные)
- Сложных архитектур с кучей разных слоев
- Когда нужно быстро получить работающий результат

**Когда лучше SGD:**

- Компьютерное зрение с классическими CNN (ResNet и др.)
- Когда память критична (обучаете модель на GPU с 4GB)
- Когда точно знаете, какой learning rate нужен
- Когда важна интерпретируемость

## Заключение: Король умер? Да здравствует король!

Adam — это, пожалуй, самый удачный компромисс в мире оптимизаторов. Он не идеален, но он **достаточно хорош** для подавляющего большинства задач. Он прощает ошибки, адаптируется к данным и стабильно работает.

В нашей реализации мы увидели:

- **Первый момент** (m) — инерция, сглаживание, направление
- **Второй момент** (v) — адаптивность, индивидуальные learning rates
- **Коррекцию смещения** — честный старт с нуля
- **Адаптивный шаг** — умное движение в пространстве параметров
